# 0004 - Love Live! 衣装图鉴双轨视觉资产录入与审核规范 (Ingestion Standards)

## 背景

本项目定位为纯粹、权威且直观的 Love Live! 衣装图鉴与三次元现实对照库。
在前期迭代中，曾出现两类严重影响图鉴体验的问题：
1. **选材阴间**：使用了背影照（看不出正面版型与配饰）、或者使用了体育馆几万人的大远景舞台合影（人物被压缩成几个像素点，被烟雾和灯海遮蔽）。
2. **冷清死板**：使用了塑料假人模特（无悬垂感、无上身穿着效果）。

为了让数据维护方（如 opencode、数据自动化采集脚本或人工录入者）有章可循，特此将**视觉资产架构、选图标准与录入规范**完全固化为正式 Spec。

---

## 一、双轨对照架构体系 (Architecture Contracts)

每套衣装在主视口中分为左右双轨：

```
+------------------------------------+------------------------------------+
| 左轨：2D 官方设定原画 (illustration) | 右轨：3D 真人模特实穿对照 (real_life) |
+------------------------------------+------------------------------------+
|  • 官方原画超清母版 (3600x1800)       |  • 真人正面对准镜头展示服装全貌      |
|  • SIFAS / 动画 / 版权绘觉醒后立绘   |  • 模特级立姿、全身或过膝半身        |
+------------------------------------+------------------------------------+
| 下方辅助轨：细节特写与证据 (detail)                                      |
|  • 头饰发饰特写 / 腰封刺绣 / 成衣打版裁剪 / 声优 Live 舞台大屏等历史证据       |
+-------------------------------------------------------------------------+
```

## 二、选图标准与铁律 (Ingestion Criteria)

### 1. 【黄金标准】`category = 'real_life'`（主实穿对照）
- **镜头视角**：必须**正对镜头（正面或最多 15° 微侧）**。
- **构图范围**：**全身立姿** 或 **过膝中景半身**。必须能够一眼看清：
  - 上身版型（领口、领结/领带、肩饰、排扣、马甲）
  - 腰部结构（腰封、腰带、蝴蝶结装饰）
  - 下身版型（百褶裙层数、滚边拼色、长筒袜/鞋靴）
- **姿态要求**：像专业服装模特展拍一样端正站立、展臂或微展裙摆，服装整体轮廓对称舒展。
- **画质标准**：文件尺寸建议 ≥ 640×853，且主体清晰锐利，无严重运动模糊与噪点。
- **来源开放**：不仅限于官方演唱会，**优先采用小红书、微博、Cosplay 社区等高质量 Coser / 模特正面精修立拍**。

### 2. 【四大红线】遇到以下情形，绝对禁止设为 `real_life`
- ❌ **绝对禁止背影**：看不到正面核心设计的背影照，一律判定为无效对照。
- ❌ **绝对禁止大球场/大远景/烟雾灯海全景**：人物在画面中占比过小、脸和衣服看不清结构的，严禁作为主对照图。
- ❌ **绝对禁止塑料假人模特/冷冰平铺作为主图**：假人模特无法反映真人穿着的自然悬垂感与比例，**必须降级标为 `detail`**。
- ❌ **绝对禁止极端暗光、大面积遮挡或严重偏色的废片**。

### 3. 【容纳规则】`category = 'detail'`（结构细节特写）
以下类型图片不作为主对照，但具有很高的辅助参考价值，统一标为 `detail`：
- 成衣打版平铺图、裁片与走线特写
- 头饰、领结、胸针、腰带花饰的微距特写
- 官方演唱会现场的大屏同框照、舞台全景远景（作为 Live 存在性佐证）

## 三、数据字段与存储规范 (Data & Storage Contracts)

### 1. 物理文件落盘
- **存放路径**：下载处理后的图片必须**同时复制落盘**至：
  - 持久化目录：`data/uploads/<filename>`
  - 前端静态目录：`public/uploads/<filename>`
- **文件命名规则**：`<角色拼音>_<主题拼音>_<类型>_<序号>.<ext>`
  - 例：`chika_aozora_cos_model.jpg`
  - 例：`shioriko_ketsui_cos_model.jpg`
  - 例：`lanzhu_colorful_dreams_cos_model.jpg`
- **格式要求**：统一转换为高质量 `.jpg`（质量 95%）或 `.png`，杜绝未处理的临时缓存后缀（如 `!nc_n_webp_mw_1`）。

### 2. 数据库记录规范 (`costume_images` 表)

| 字段 | 类型 | 规范说明 |
| :--- | :--- | :--- |
| `id` | TEXT | 全局唯一 ID，如 `img-takami-chika-real-model` |
| `variant_id` | TEXT | 关联的外键，如 `variant-chika-aozora-jumping-heart` |
| `file_path` | TEXT | 统一使用绝对根路径：`/uploads/<filename>` |
| `category` | TEXT | `'illustration'` \| `'real_life'` \| `'detail'` |
| `is_primary` | INTEGER | 该分类下的主展示图为 `1`，其它为 `0` |
| `caption` | TEXT | 结构化描述：包含角色名、曲目衣装名、服装关键特征、出处作者（如“小红书@_1743_ 出片”） |
| `sort_order` | INTEGER | 排序序号，主图为 `1`，细节图顺次递增 |

### 3. 来源依据出处 (`costume_sources` 表)
任何录入的图片必须在 `costume_sources` 中有迹可查：
- `source_type`: `'game_card'` / `'cosplay_photo'` / `'live_stage'` / `'anime'`
- `title`: 明确标出平台、作者与作品名（例如：`小红书 @_1743_ 青空Jumping Heart 正面直拍展示`）
- `url`: 真实的来源网页链接，支持用户点击溯源
- `detail`: 简述该出处的参考特征

## 四、opencode 补图作业标准流程

1. **抓取检索**：使用小红书/微博/图库检索 `<角色名> <打歌服/曲名> cos` 或 `<角色日文名> 衣装`；
2. **视觉筛选**：遵循**“正面、半身/全身、像模特展示衣服一样、绝无背影和远景”**标准筛选出 1 张最佳正面实穿照；
3. **文件写入**：下载并转存至 `data/uploads/` 与 `public/uploads/`；
4. **数据同步**：
   - 执行 INSERT / UPDATE 将新图写入 `costume_images`（`category = 'real_life'`, `is_primary = 1`）；
   - 将原有的远景或假人图降级为 `category = 'detail'`, `is_primary = 0`；
   - 写入 `costume_sources` 记录作者和链接。
5. **验证**：运行 `pnpm test` 保证全部通过，并在 `http://localhost:5173` 上肉眼核查双轨并排效果。
