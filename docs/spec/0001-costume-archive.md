# 0001 - Love Live! 衣装资料库

## 背景

本项目旨在为个人打造一个轻量、清晰、可逐渐扩展的 **Love Live! 角色与衣装本地资料库**。
核心使用场景是：当用户在浏览、收集或准备 COSPLAY 时，面对某套服装图片，能够便捷地通过企划团体或角色检索到该衣装的日文原名、中文译名、对应人物立绘以及原始出处（例如动画话数、手游卡面觉醒前/后、声优 Live 舞台服、CD 封面等），避免名称混淆与考据困难。

## 用户场景

1. **查找特定角色的服装出处**：用户想做一套“三船栞子”或“安养寺姬芽”的演出服，进入该角色页面即可浏览其所有收录衣装，点击卡片能查看大图与官方出处链接。
2. **多角色同套主题服装查阅**：例如团体全员曲或分队服装，在同一主题下每位角色具有独立的服装细节与立绘图片。
3. **未考据衣装先行收集（待识别录入）**：用户在社交平台或 COS 图片中看到一套服装，但暂未查证到官方日文正式名称；允许用户先录入图片并标记为“待识别”，严禁编造正式名称，待考据确凿后再补全。
4. **声优 Live 与游戏觉醒形态区分**：用户需精准查找“某场声优现场 Live 实际演出服”或“Link! Like! / SIF 卡面觉醒前生活服 vs 觉醒后舞台服”，可通过专门的结构化维度直接筛选。
5. **本地资料维护与安全备份**：用户在本地录入或修正信息，数据完全保存在本地；提供简便的本地一键备份与恢复方案，防止误删或重装导致资料丢失。

## 需求

### 模块 A：企划与角色

1. **团体目录与历代动态阵容**：
   - 收录 Love Live! 主要企划与团体，包括 μ's、Aqours、虹咲学园学园偶像同好会、Liella!、莲之空女学院学园偶像俱乐部、いきづらい部等。
   - 角色模型支持记录加入期数/年度、活动状态（`在籍/现役`、`毕业生/历史成员`）以及不同活动时期的组合归属（例如莲之空从 102 期至 106 期成员、瑞河女子与 Edel Note 相关历史；虹咲各分队与本团）。
   - **人数动态统计**：首页与团体列表中的人数**必须由实际收录数据动态聚合计算**（支持按“当前在籍”与“历代全员”切换查看），严禁前端代码硬编码写死人数。
   - 历史毕业成员与相关衣装**永久保留**并可检索。
2. **角色归属**：数据模型支持一个角色关联多个团体或历史分队。
3. **角色专属页**：点击角色卡片进入其专属衣装图鉴页；首期基本个人信息留空不强求填写。

### 模块 B：角色衣装图鉴（核心）

1. **衣装卡片展示**：每个角色页面展示该角色已收录的衣装卡片列表。
2. **卡片字段与状态**：
   - 衣装日文原名（考据确凿后填入；若尚未考据出，允许置空或临时占位，命名状态标为 `待识别`，严禁编造伪正式名称）
   - 中文名称（可选）
   - 衣装参考图片（支持多图或主图）
   - 所属角色（关联至角色）
   - 衣装所属主题/系列（例如单曲名称、活动主题、live 巡演名称）
   - 来源类型（动画、手游卡面、声优 Live、CD 封面、版权绘等）及来源参考链接
   - **手游卡面特态**：若来源为手游卡面，须提供专门字段区分 `觉醒前` / `觉醒后`（可用于过滤筛选）
   - **声优 Live 特态**：若来源为真人现场 Live 演出服，须标记具体场次与 Live 属性
   - 核实状态：`已核实` / `待核实`
3. **详情弹窗/大图浏览**：点击卡片可查看高清大图、多角度参考图及完整考据信息与可复查的出处外链。
4. **主题复用与独立图片**：同一衣装主题允许关联多位角色，且不同角色保存各自独立的服装立绘/参考图。

### 模块 C：资料编辑与本地持久化

1. **新增与修改衣装**：支持录入与编辑衣装各字段，支持暂存为“待识别”或提交为“待核实”。
2. **“已核实”后端强制校验**：
   - 标记为“已核实（verified）”的记录，后端 API 必须进行严格证据校验：**必须具备有效的日文原名**，且**必须包含至少一条带有效可访问 URL 及标题的来源证据**；不满足条件时后端强制拒绝转为已核实状态，不可只靠前端弱限制。
3. **本地图片存储**：从本地选择图片文件并复制保存至应用的本地媒体库目录中，防止外链失效。
4. **本地数据备份与恢复**：
   - 提供轻量的本地备份与恢复机制（导出包含 SQLite 数据库与上传图片目录的本地快照包），确保误删或重新安装时可完整还原。

### 边界与异常

1. **空状态处理**：角色尚未录入衣装时，展示友好的空状态（Empty State）提示，严禁编造虚拟数据占位。
2. **缺失字段处理**：无图片或部分可选字段（如中文名、来源链接）为空时，卡片与详情页正常排版，不得崩溃。
3. **已核实真实性**：标记为已核实的数据必须在后端经过证据链校验，无确切依据者一律保持“待核实”或“待识别”。
4. **图片格式容错**：支持常见图片格式（PNG、JPG、JPEG、WebP），图片损坏或丢失时显示统一的占位图并提示缺失。

## 验收标准

- **AC-1（正常浏览）**：启动应用后，进入 虹咲学园学园偶像同好会 → 三船栞子 → 衣装，能清晰看到对应的图片、衣装日文名、主题及来源出处。
- **AC-2（修改后更新）**：打开任一衣装记录，修改名称并保存，返回列表后新名称即刻呈现；刷新浏览器页面，新数据依然保持。
- **AC-3（持久保存）**：录入一条新衣装记录并上传本地图片，完全关闭服务进程再重新启动，该记录及图片依然完整可访问。
- **AC-4（缺失数据容错）**：访问无衣装的角色或无图片的衣装记录，页面优雅展示占位/空状态，控制台无致命报错。
- **AC-5（资料可信度）**：核对标记为“已核实”的首批样例数据（三船栞子、上原步梦、安养寺姬芽），能通过来源链接直接检索并印证对应服饰出处。
- **AC-6（待识别衣装录入）**：录入一套尚未考据出日文原名的衣装，系统允许保存为“待识别”状态，界面不虚构名称，待后续考据补充。
- **AC-7（声优 Live 与卡面觉醒状态精准筛选）**：支持在图鉴列表中通过专门的筛选项精准过滤“声优 Live”演出服，或单独筛选“手游觉醒前”与“手游觉醒后”衣装。
- **AC-8（“已核实”后端强校验）**：在缺少有效官方日文名或缺少有效来源链接的情况下，尝试将记录保存为“已核实”，后端返回 400 校验错误并拦截；补全有效证据后方可成功保存。
- **AC-9（本地备份与恢复）**：运行备份指令或导出快照，生成完整的离线备份文件；在清空或迁移数据后执行恢复，数据库记录与图片资源完整复原。
- **AC-10（历代成员动态统计与历史保留）**：团体人数由底层数据实时 COUNT 聚合生成；莲之空各期历史成员（包括 102 期至 106 期及相关组合）与历史衣装完整保留，可按在籍/历代模式准确查阅。

## 非目标

1. 首版不做 AI 自动识图/特征比对。
2. 首版不做全网爬虫自动化抓取。
3. 首版不包含 COSPLAY 商城/购买链接比价及商业导流。
4. 首版不做广播剧、生放送、动画等全量时间线轴播放。
5. 首版不引入多用户账号体系、注册登录及云端同步（纯本地应用）。
6. 首版不专门针对移动端做特殊深度适配（以桌面端/平板宽屏为主）。
