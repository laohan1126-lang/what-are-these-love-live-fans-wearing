# 0003 - Love Live! 衣装图鉴与自动化考据采集流水线

## 背景

在 v0.3 版本中，系统完成了基础数据存储、展示画布与严谨的数据校验规则。
然而，用户并不希望在本地手工一张张收集、裁剪和录入图片，也不需要复杂的裁缝制衣拆解工单。
用户核心诉求是建立一个**纯粹、完整、权威的 Love Live! 衣装全图鉴（Illustrated Encyclopedia / Pokedex）**。
该图鉴的建立依赖**自动化采集脚本检索下载**，并由 **Agent 进行权威考据核验与真伪校验**，免去人工收集成本，直接为用户呈现全企划各角色的完整衣装档案。

---

## 用户场景

1. **一键充实角色图鉴**：用户选择某个角色（如“三船栞子”或“安养寺姬芽”），系统执行采集流水线，自动检索官方数据库与维基，下载该角色的正规打歌服、卡面觉醒服、Live 服饰及日文原名，自动入库。
2. **纯粹沉浸式图鉴浏览**：用户打开应用即可像查阅宝可梦图鉴一样，清晰查看各角色收录的所有服饰卡面与立绘，按出处（动画、卡面觉醒前/后、声优现场 Live、CD 封面等）自由筛选。
3. **图鉴全收集进度追踪**：每个团体、每个角色展示清晰的收集度指标（如“三船栞子：18套收录”、“虹咲学园：142套收录”），直观掌握收录完备度。
4. **Agent 考据把关，杜绝假数据**：由自动化脚本初步抓取候选数据，Agent 自动比对官方日文正式名与可溯源外链；不确定的标为“待核实”，确凿无误的打上“已核实”认证，保障图鉴的权威性。

---

## 需求

### 模块 A：自动化采集与下载脚本流水线 (Scraper & Fetcher Pipeline)

1. **权威数据源连接**：
   - 接入结构化社区/维基数据源（如 Fandom Love Live! Wiki / MediaWiki API、Idol.st / School Idol Tomodachi API、Moegirlpedia 官方打歌服目录）。
2. **多维度元数据抓取**：
   - 官方日文原名（如《決意の光》、《EMOTION》、《Dream Believers》、《青空Jumping Heart》等）
   - 中文译名/常用称呼（可选）
   - 所属角色（精准映射至系统已有角色 ID）
   - 所属主题/曲目/卡面名称
   - 出处类型（`手游卡面`、`声优 Live`、`动画`、`CD 封面`、`版权绘`）
   - 细分形态标记（手游卡面区分 `觉醒前` / `觉醒后`；Live 区分演出场次）
   - 权威参考来源 URL（必须为可访问的官方/维基条目直链）
3. **高清图片抓取与本地落盘**：
   - 自动化下载高品质立绘/卡面原图，安全转存至 `public/uploads/` 目录，命名规则结构化（如 `char_{id}_{costume_slug}.jpg`）。
   - 本地去重：相同图片或相同卡面 ID 自动跳过，不重复下载占用磁盘。

### 模块 B：Agent 考据与入库闸门 (Verification Gate)

1. **严格真伪把关**：
   - 采集入库时，自动校验日文名真实性与来源 URL 有效性。
   - 满足强证据链的记录赋予 `verified = 1`。
   - 来源存疑或非正式别名的记录标记为 `verified = 0`（待核实）或 `is_unidentified = 1`（待识别），严禁凭空捏造。
2. **批量入库与事务安全**：
   - 采集结果通过标准 API 或 CLI 批量写入 SQLite 数据库，保证数据一致性。

### 模块 C：纯粹的图鉴展示与收集度体验 (Pokedex UI)

1. **图鉴模式看板**：
   - 彻底聚焦于“图鉴浏览”与“收集度”，移除任何与做衣服、裁缝工单相关的非核心交互。
   - 顶部或侧边展示全团/各角色衣装收集计数徽章（如 `18 套已收录`）。
2. **全景画廊与胶卷舞台**：
   - 选用高辨识度的大图舞台 + 底部缩略胶卷，支持全屏原画检视。
   - 明确标注日文原名、出处形态、关联歌曲。
3. **快捷维度筛选**：
   - 一键筛选：全部、手游卡面（觉醒前/后）、声优 Live、动画舞台服、CD 封面。

### 模块 D：CLI 与后台触发指令

1. **提供一键同步脚本**：
   - 支持针对特定角色同步：`pnpm run curate --character "三船栞子"`
   - 支持针对特定企划团体同步：`pnpm run curate --group "虹咲"`
   - 支持全量增量更新：`pnpm run curate --all`

---

## 边界与异常

1. **网络超时与反爬限制**：
   - 抓取脚本需配置 User-Agent 与请求节流（Rate Limiting，默认每次请求间隔 500ms~1000ms），避免被目标数据源限流。
2. **无正式衣装名称的情形**：
   - 部分卡面或生活服官方未冠以独立衣装名，系统自动以 `[卡面名/活动名] 演出服` 规范标注，或标为待核实，不得杜撰名称。
3. **图片下载失败处理**：
   - 若某张图片下载失败或外链损坏，记录错误日志并跳过该张，不阻塞整体流程；数据库中若无本地图片则降级使用优雅占位图。

---

## 验收标准

- **AC-1（自动化采集脚本运行）**：运行采集命令（如 `pnpm run curate --character "三船栞子"`），脚本成功联网请求合法数据源，解析出至少 5 套真实官方衣装数据。
- **AC-2（图片自动下载与本地化）**：采集完成后，相关衣装的高清图片已完整保存至 `public/uploads/` 本地目录，服务断网状态下亦可正常浏览加载。
- **AC-3（数据准确性与证据链）**：入库的每一套已核实衣装，其日文原名均与官方/维基记载完全一致，来源链接真实有效。
- **AC-4（图鉴 UI 展示与大图浏览）**：刷新前端页面，三船栞子等角色的图鉴列表实时呈现抓取到的所有衣装卡片，点击即可在大图舞台中高清欣赏。
- **AC-5（卡面觉醒前/后与 Live 分类准确）**：抓取到的游戏卡面服饰能准确标识“觉醒前”或“觉醒后”，声优 Live 准确标注演出场次，且前端分类筛选器能精准过滤。
- **AC-6（收集度计数实时更新）**：角色卡片与导航区中的收录套数从原先的少量样本，实时动态更新为实际抓取入库的数字（如 `12 套`）。
- **AC-7（增量去重防重复）**：再次运行相同角色的采集指令，系统自动识别已有记录并跳过，不会产生重复卡片或冗余垃圾文件。
- **AC-8（异常与限流容错）**：遇到网络异常或目标图片 404 时，脚本优雅报错并继续处理下一项，终端与数据库均无未捕获崩溃。

---

## 非目标

1. 不做裁缝制衣工单、尺寸量体、布料色板拆解等服装制作功能。
2. 不要求用户手工从本地逐张上传图片（全部由自动化采集下载负责）。
3. 不做用户端全网无目标黑盒爬虫（限定在已验证的 Love Live! 权威数据库与结构化 API 范围内）。
4. 不做收费商城、二手转卖或 COS 服购买外链导流。
